## 🎯 这是什么

**飓风接力**是面向专业内容团队的 **AI 内容中间件**——解决视频端到端的信息流转效率。

一条 20 分钟的频道视频完成后，运营要从中提炼分发文案，电商要从中截取产品素材并翻译卖点，市场要从中规划投放策略。每多一个下游角色，就多一次完整的线性观看。

StormRelay 让 AI 先看完视频，输出结构化的中间产物，下游角色各取所需。**剪辑师的工作从「写交接文档」降级为「扫两分钟确认 AI 写的对不对」，下游的工作从「盲看 20 分钟视频」变成「带着地图找重点」。**

两条平行管线，共享同一个视频理解的上下文，避免重复分析：

- **交付管线**：剪辑 → 运营（视频交接信息的结构化）
- **电商管线**：从同一视频中提取产品出镜片段，把拍摄参数语言翻译为消费者语言

## 💡 为什么做这个

### 问题的本质

内容团队提效的瓶颈，往往藏在交接环节里。

剪辑师用上 AI 剪得更快了，运营用上 AI 写得更快了——但各自省下来的时间，散落在项目与项目之间的交接缝隙里，凑不成一块完整的创作时间。单点加速解决的是个人效率，端到端的信息流转效率才决定团队的产出节奏。

问题出在两头：

- **上游**：剪辑师刚从创意模式（节奏、色彩、情绪）出来，切到文档模式写结构化交接信息，认知模式切换成本极高。结果就是交接文档要么不填，要么敷衍两行。
- **下游**：视频是线性锁死的信息容器——不能 Ctrl+F、不能筛选。运营要看一遍、电商再看一遍、市场又看一遍，同一条视频被线性消费三次。

> 飞书能加字段吗？能。但容器不是瓶颈——填写成本才是。加了字段没人认真填，和没加一样。

### 解决思路

![产品界面总览](screenshots/01_project_list.png)

AI 看视频写结构化草稿 → 剪辑师扫两分钟确认 → 下游各取所需

真正要做的是把工作全流程拆到最细粒度，找到信息损耗最大的环节——然后把 AI 放在那个位置上。对内容团队来说，这个位置就是视频完成后、各岗位开始工作前的那个交接节点。

### 从个人工具到组织能力

传统提效工具给每个人装一个 AI 助手，边际效应很快到顶。StormRelay 走的是另一条路：

- **L1**：AI 帮个人生成素材——每个岗位各自加速，链路总耗时基本不变
- **L2**：AI 翻译跨角色认知——交付管线 + 电商管线共享上下文，信息流转方式变了
- **L3**：AI 沉淀组织经验，自动完成全流程，人做审核——Skill 自进化体系

StormRelay 当前聚焦在 L2，目标是 L3。

## ✨ 核心功能

### 1. AI 智能提取

![AI标注卡片](screenshots/02_ai_cards.png)

基于火山引擎视频理解API（豆包大模型 Doubao-Seed-2.0-pro），自动提取：

- 🎯 **核心定位**：一句话概括视频的目标人群和价值主张
- 💡 **核心卖点**：3-5个关键卖点，带出品方标注（自研/合作/友商）
- ⏱️ **关键时间点**：适合截取短视频或封面的精彩片段
- ⚠️ **注意事项**：可能引发争议或需要说明的风险点

### 2. 剪辑视角 —— 2分钟确认

![剪辑视角](screenshots/03_editor_view.png)

- ✅ 勾选确认 AI 提取的信息
- ✏️ 编辑修改不准确的内容
- ➕ 添加 AI 遗漏的要点
- 🚀 一键交付给运营

### 3. 运营视角 —— 3分钟上手

![运营视角](screenshots/04_operator_view.png)

- 📋 结构化信息卡，一目了然
- 📝 添加运营笔记，记录分发策略
- 🤖 查看 AI 总结，快速理解视频
- 📁 标记上线归档

### 4. 电商视角 —— 平行管线

![电商视角](screenshots/07_ecommerce_view.png)

电商管线和交付管线并行运行，共享同一个视频理解上下文，独立于项目交付状态：

- 🛒 **产品出镜识别**：AI 自动识别视频中产品出镜片段，标注时间戳
- 🔄 **卖点翻译**：把「拍摄参数语言」翻译为「消费者语言」（如 "3M新雪丽棉" → "雪地生存100小时实测，穿暖了"）
- 💡 **拍摄建议**：基于当前素材质量给出下次拍摄的优化建议
- 📈 **电商价值评估**：预估可产出的详情页素材、短视频切片、小红书素材数量

电商是内容变现的关键出口。一条视频的商业价值，很大程度上取决于电商团队能多快、多准地把视频内容转化为可售卖的素材和话术。这条管线直接影响内容到收入的转化效率。

### 5. 效率看板

![效率看板](screenshots/08_analytics.png)

度量的重点放在信息流转质量上，关注 AI 对端到端交付的真实影响：

- 🎯 **AI 标注采纳率**：核心指标（目标 ≥ 70%）——AI 输出的东西有多少被人认可，这比生成数量重要得多
- 📉 **下游追问频次**：运营拿到 AI 结构化信息后，还需要反复找剪辑师确认多少次——这个数字直接衡量信息流转是否顺畅
- 🛒 **电商素材产出**：跨项目的素材识别总量、确认量、涉及产品数
- 💡 **卖点关键词云**：从卖点和消费者语言中提取高频词

### 6. Skill 工作台（Beta）

![Skill工作台](screenshots/09_skill_workbench.png)

AI 从团队实际操作中自动沉淀可复用打法——这是从 L2 走向 L3 的基础：

- 🌳 **能力树**：底层通用 Skill → 中层场景 Skill → 表层任务 Skill
- 📐 **评判准则**：四条可编辑原则（能力进化、定时自省、反退化锁、能力树约束），决定什么能被沉淀
- 🤖 **AI 自省建议**：基于项目数据自动生成 Skill 管理建议
- 🔒 **人始终有控制权**：编辑、冻结、删除任何 Skill，导出到飞书

## 🛠️ 技术实现

### 文件结构

```
飓风接力/
├── index.html          # 项目列表页
├── project.html        # 项目详情页（三视角 + 电商平行管线）
├── upload.html         # 视频上传页
├── settings.html       # AI 配置页
├── analytics.html      # 效率看板（实时数据汇总）
├── knowledge.html      # Skill 工作台（Beta）
├── styles.css          # 共享样式
├── app.js              # 共享逻辑（数据管理 + 数据版本控制）
├── api/
│   ├── analyze.js      # 视频分析 API 代理
│   └── upload.js       # 文件上传 API 代理
├── icon/               # 图标资源
└── screenshots/        # README 截图
```

### 技术栈

- **前端**：原生 HTML + CSS + JavaScript
- **风格**：Linear 风格，简洁专业
- **数据**：localStorage 本地持久化 + 数据版本控制
- **后端**：Vercel Serverless Functions
- **API**：火山引擎视频理解（豆包大模型 Doubao-Seed-2.0-pro）

### API 调用架构

```
前端 ──POST──→ /api/analyze ──转发──→ 火山引擎 Responses API
                  ↓
         Vercel Serverless Function
         （处理鉴权、转换格式、解析响应）
```

## 💡 关于飞书

> 飞书多维表格加 AI 字段，技术上完全做得到。实际落地大概率就是飞书生态内的一个模块。

> 做什么比用什么做重要。洞察是核心，技术方案是可替换的。

## 🎁 彩蛋

### HKRR 原则

在 AI 配置页的提示词模板中，植入了影视飓风的内容评判标准：

- **H**appiness（快乐）：利用幽默的开场白或轻松的语言风格
- **K**nowledge（知识）：传达核心信息、原理解析或实用方法
- **R**esonance（共鸣）：描述观众熟悉的场景或情感
- **R**hythm（节奏）：通过画面切换和剪辑速度保持注意力
